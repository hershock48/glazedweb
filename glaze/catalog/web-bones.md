# Web bones: components and flows worth a session

| Bone | Lives in | What it is |
|---|---|---|
| Glazed credit + plate | `glaze/assets/glazed-credit/` | The studio credit, JSX/TSX/CSS, drip edge included. Already canonical — the model for how a bone graduates. |
| Scooplist site fetcher | `glaze/assets/scooplist-feed/` | Server-only feed client for any site fed by a Scooplist deployment: section map (board key → mapper + static fallback), mapAll strictness (one bad row falls the whole section back), per-section independence, code-default feed URL with `SCOOPLIST_FEED_URL` override, org path support for the multi-org deployment. Graduated from `truenorth/src/data/liveCase.ts` and `cascarellis/src/data/liveBar.ts` when copperac became the third consumer. Pair it with a copy of truenorth's `/api/status`. |
| Booking scheduler (Calendly, owned) | `migas/lib/slots.ts` + `lib/availability.ts` + `lib/busy.ts` + `lib/ics.ts` + `app/admin/` (origin, TS, fullest comments) · `glazedweb/lib/schedule.js` + `app/(en)/schedule/` (older live instance, static windows) | Weekly-pattern slots rendered as real radios (works scripts-off), hand-rolled RFC 5545 invites (Zulu instants, folded lines). Since 2026-08-27 the migas copy is the full loop: owner-editable windows at `/admin` (PIN gate, one Blob-stored JSON, zero client JS), an iCal busy feed that drops or shortens covered slots (RRULE counted+logged not expanded, every failure open), and server-side re-validation against the same live sources. Port the migas copy, not glazedweb's. |
| Year counter | `Schulers/components/YearCount.jsx` | Count-up number with a visibility-gated rAF clock and a solved cubic-bezier. Survived three broken mechanisms (scroll-scrubbed, fired-once timer, WebKit-frozen CSS counter); its header records all three. Read it before building ANY count-up. |
| Inline reserve strip | `Schulers/components/ReserveStrip.jsx` | Homepage booking entry that carries choices into the real form instead of pretending to check availability. The mobile grid layout is load-bearing — see the 620px comment for the iOS collapse it fixes. |
| Reservation + host stand | `Schulers/app/reservations/`, `app/host/` | Booking form on one side, tonight's covers by half-hour on any tablet on the other; slots self-mark full. |
| Banquet inquiry | `Schulers/components/BanquetInquiry.jsx` | Event inquiry that narrows to the rooms that fit and reroutes oversize parties. |
| Gift card flow | `Schulers/components/GiftCardForm.jsx` | Amount / recipient / message / delivery-date with demo checkout. |
| Open-now badge | `Schulers/components/OpenNow.jsx` | Hours logic rendered as a live open/closed state. |
| Self-drawing artwork | `Schulers/components/BuildingInk.jsx`, `CrestSignature.jsx` | The rendered halves of the pipelines in pipelines.md. |
| Magic-link auth | `beanumber/src/app/signin/` + `/api/sponsor/recover/` | Email link → session cookie → deep-link to the page the email promised; the token carries the destination. Sign-in-first with intent passthrough (`?intent=sponsor` rides to checkout). |
| Gated documents | `beanumber/src/app/children/[number]/ChildDocuments.tsx` + the gate in `page.tsx` | Entitlement enforced at the data layer so public-by-URL storage links never reach an anon payload. The pattern, not just the component. |
| Penpal engine | `beanumber/src/app/children/[number]/` (PenpalBox and kin) | Correspondence UI with per-viewer states (anon / holder / sponsor), each carrying exactly one ask. |
| Dietary/menu data | `pjs`, `cookinwithbeans`, `copperac`, `stagecoach`, `Schulers` | Menu-as-data with prices in mono, leaders drawn by scroll. The shape recurs; the newest copy is usually the best. |
| Cart + checkout (Stripe) | `sprinklesandsparklesbb/app/` (digital downloads, webhook-gated), `louies/app/` (physical + shipping), `superduper/app/`, `kidniche/app/` | Four carts at different weights. sprinkles is the reference for digital delivery: `/api/download/[slug]` gated on the Stripe webhook. |
| Quote engine | `anchor/app/quote/`, `/api/quote` | Multi-step insurance quote intake with a received state and a ledger. |
| Client intake sheet (draft-protected) | `anchor/app/intake/`, `/api/intake`, `components/IntakeForm.tsx` | The glaze/intake.md question list as a page the client fills in herself, linked from the proposal's closing ask. Everything optional but the name. Plain POST underneath; JS layers on a localStorage draft (saved per keystroke, flushed on pagehide, restored into empty fields only, cleared only after a confirmed send) and a fetch submit that fails in place with the answers still on screen. Delivery over Resend, payload always logged first. The shape for onboarding any client without round-tripping a Word document. |
| Bill-pay page (carrier routing + parked invoice checkout) | `anchor/app/pay/`, `/api/pay` | The honest payments page for a business that mostly does NOT collect the money: one row per carrier pointing at that carrier's own portal and billing phone, plus a flag-parked Stripe dynamic-amount checkout for agency-billed invoices (customer types name, policy, amount from the bill they already have — the bill is the ledger, the site is the till, no accounts). API refuses independently of the page flag; agency emailed BEFORE the Stripe redirect (louies' no-webhook lesson); amount cap because typos add zeros. Fiduciary flip-checklist lives on the flag in `lib/site.ts`. The shape for any regulated or pass-through payment where collecting wrongly is worse than not collecting. |
| Order intake, no card (SMTP ticket) | `devine/src/lib/intake.ts`, `/api/order`, `components/CartView.tsx` | Checkout that emails the shop a plain-text worksheet ticket and takes payment on the confirm call. Server-side pricing from the catalog, three honest states (sent / unconfigured / send-failed — the last two hand the visitor a prefilled mailto, never a false receipt), off-list-zip flag on the ticket instead of a wall. The shape for any client who takes orders by phone today. |
| PIP calculator | `anchor/app/tools/michigan-pip/` | A public calculator as a content-marketing tool — the shape for "useful widget that earns links." |
| Seasonal engine | `devine/src/lib/seasons.ts` + `components/Season.tsx` + `/api/season` | The site turns with the calendar on its own, zero upkeep: four premade seasons as the base (one accent token repointed per season under a `data-season` wrapper, hero copy variants, a curated featured list per season) with the flower holidays highlighted on top as each approaches (Valentine's, Easter by Computus, Mother's Day, Sweetest Day, Thanksgiving, Christmas — every date computed, never stored, in the shop's timezone). A cookie-backed preview route flips the whole year across a table, which is also how the states get audited. Demo tree must render per request (glaze.md: route caching and time do not mix). The shape for any client whose sales turn with seasons or holidays. |
| Client photo drop (asset intake) | `devine/src/app/photos/` + `/api/photos`, list derived in `src/lib/photos.ts`, ledger in the workroom store | The client uploads her own missing product photos from her phone: the needed list is DERIVED (catalog minus image manifest, so every photo that goes live removes its own row on the next deploy), each shot is downscaled in the browser to 1800px JPEG (EXIF orientation baked, <img> fallback decode, honest error offering to text it), emailed to Glazed the moment it is picked (never batched: a batch dying at 30 of 34 loses thirty), and a per-slug ledger row with a ~16KB thumbnail is the saved progress, visible cross-device. Completion emails Glazed by itself. No PIN: worst abuse is emailing Glazed pictures, throttled. Pairs with `tools/ingest-photo.mjs` (pipelines.md). The shape for any client owing the site assets. |
| Custom-order clickwrap acceptance | `devine/src/app/agreement/` + `/api/agreement`, facts in `src/lib/agreement.ts` | The digital signature for Custom Orders: v1.0 terms incorporated by reference (linked, never restated), Exhibit A rendered from a constants file, typed-name + checkbox acceptance where the email to both parties is the record (version, exhibit, timestamp, IP) and a DB row is the queryable duplicate. Honest failure states hand the visitor a prefilled mailto carrying the server's own record text. The shape for signing any custom client without renting an e-signature service. |
| Square register link (POS sync + OAuth + platform fee) | `devine/src/lib/square/` + `/api/square/*` | Two pipes behind a shop's existing Square register: catalog pushed onto the register with the product slug written into each variation SKU (so no id mapping is ever stored, and items that are the shop's own are counted as strays and never touched), and every completed payment ingested back over a signature-verified webhook into a `square_sales` table, line items mapped to catalog slugs by SKU. Raw fetch, no SDK; sandbox unless `SQUARE_ENV` literally says `production`. Production auth is OAuth through the Glazed-owned developer app (`oauth.ts`: HMAC-signed stateless state, grant in a `square_oauth` table, lazy 30-day refresh, env-token fallback), which is the only token type that can carry `app_fee_money`; `payments.ts` holds the card-payment helpers with the 99c platform fee riding inside the payment to the Glazed Square account, including `chargeBoardOrder` (API-created order + payment, ad hoc lines, fee line, reference_id linkage). `workroom/PayControls.tsx` + `/api/workroom/pay` + `/api/workroom/square-web` are the counter-side half: card keyed via the Web Payments SDK or cash recorded on the order card, webhook links the sale back and inventory dedupes. Register-side collection of API orders is NOT viable (unsupported per Square staff 2026-08-18); this is the supported shape. For any client who rings a Square counter and wants one system of record. |
