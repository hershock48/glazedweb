## What AOA has that the pipeline does not

Ganim's process, in his words: audit how they do a process today, optimize
it by cutting steps, automate what is left into a skill or a scheduled task.
He runs a ten-minute intake form before the first call, opens with "what
would make this a win in 90 days," ships one automation on call one, and
keeps three markdown context files per client (about, brand voice, working
preferences) that Claude writes by interviewing the owner. His own back
office is four skills: intake to project files, call transcript to a log
entry, follow-up email draft, and an orchestrator that runs the last two.
The "split at every human or wait" rule was not found in any fetched source
and lives in the unresolved video, so treat the phrasing as his but the
evidence as thin.

Applied to the studio:

1. **A post-call skill.** Transcript or notes in, ledger event and a drafted
   follow-up out. This is the exact hole the 2026-09-13 ledger memory names.
   Draft only. `close.mjs` already drafts follow-ups from registry needs; the
   missing half is the intake side, a meeting written up the same day.
2. **Per-client context files.** `glaze/clients/*.md` holds durable facts.
   A `voice.md` beside each, built from the owner's own words on the call,
   is what every copy script should read before writing for that client.
   The house voice lives in `glaze.md`; the client's does not exist yet.
3. **An Optimize gate before any new script.** Write the manual steps down,
   strike the ones that exist by accretion, then automate what is left. The
   ledger, close and research chain grew in three days; it has not had this
   pass.
4. **As a service line.** A $1,200-a-month retainer does not fit a diner
   owner with no desk time. A narrowed version does: an ops audit at the
   register (order flow, menu changes, review replies, catering inquiries)
   as the front door to the ordering build, then a $50 to $150 monthly layer
   of draft-only skills on top of the ordering data the studio already
   holds. That sits inside the Square floor rule and the "brain behind the
   register" focus. Pricing is Kevin's call; nothing here is on a page.

## Running things on a schedule without an API key

Verified against Anthropic's own pages on 2026-09-16.

- **`claude -p` draws from the Max subscription.** The support article
  "Use the Claude Agent SDK with your Claude plan" says the planned change
  was paused on June 15, 2026 and "nothing has changed: Claude Agent SDK,
  `claude -p`, and third-party app usage still draw from your subscription's
  usage limits." Source: https://support.claude.com/en/articles/15036540
- **`--bare` is the trap.** The headless docs: "In bare mode, Claude Code
  never reads OAuth credentials or the system keychain." It needs
  `ANTHROPIC_API_KEY`, and the docs say bare will become the default for
  `-p` in a future release. A Max user who left the key exported and ran
  `-p` on a schedule got an API bill (claude-code issue 37686). Rule for any
  glaze runner: never pass `--bare`, refuse to start if `ANTHROPIC_API_KEY`
  is set, pass explicit `--allowedTools`, use `--output-format json`, and
  branch on the exit code. Source: https://code.claude.com/docs/en/headless
- **What is not allowed.** Lifting the subscription's OAuth token into any
  other tool, harness or SDK package. The official CLI, the desktop app's
  scheduled tasks, cloud Routines, and the in-session loop are the permitted
  surfaces, and all are on Max. Source:
  https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546
- **Desktop scheduled tasks** read local files and keep the prompt in
  `~/.claude/scheduled-tasks/<name>/SKILL.md`. None exist on this machine
  yet. That is the right home for a morning digest that runs `ledger.mjs`
  and a nightly reply check. Source:
  https://code.claude.com/docs/en/desktop-scheduled-tasks
- **Codex** documents `codex exec` for scripts on a ChatGPT login, which is
  what `second.mjs` already does. Source:
  https://learn.chatgpt.com/docs/non-interactive-mode

## Patterns worth adopting, from the skill ecosystem

- **Doctrine as skills, not one long system prompt.** The Agent Skills spec
  (https://agentskills.io/specification, https://github.com/anthropics/skills)
  wants a `SKILL.md` with a "Use when" description under 1,024 characters, a
  body under 500 lines, references one level deep, and `metadata.version`.
  `research.mjs` and `second.mjs` already read sections of `prospecting.md`
  and `standards.md` at run time; cutting those sections into skills makes
  the same rules load in Claude Code and in Codex.
- **No skill without a failing run first.** obra/superpowers writes skills
  the way tests are written: run the scenario without the skill in a
  subagent, record the bad output verbatim, write the smallest rule that
  fixes it, run again. The "no AI prose tells" rule is the obvious first
  drill. https://github.com/obra/superpowers
- **The triplet contract.** product-on-purpose/pm-skills ships every
  business skill as `SKILL.md`, `TEMPLATE.md`, `EXAMPLE.md`, with CI that
  fails when one is missing. That is Ganim's "a reference file is an example
  of what good looks like," enforced. https://github.com/product-on-purpose/pm-skills
- **Distribute with `npx skills`.** vercel-labs/skills installs a skill
  folder from one git source into `.claude/skills/` and Codex's
  `.agents/skills/` in every repo, non-interactively. One source for all
  hershock48 repos. https://github.com/vercel-labs/skills
- **Draft-only credentials, not draft-only prompts.** Every serious outreach
  project makes the send a human click by withholding the send scope from
  the agent (gogcli's no-send policy, the scope-gated Gmail MCP). A prompt
  that says "never send" is a request; a token without the scope is a fact.
- **Shadow mode before auto mode.** The two Google review-reply projects
  found (TuanPhan17/Google-Ai-Review-Responder, binesheb/google-review-autoreply)
  both route one-to-three-star reviews to a human always and run new
  automations in draft, then shadow (generate, do not act, diff against what
  the owner did), then limited auto with a daily cap. The Google Business
  Profile API needs a formal access application with quota at zero until
  approved, so review replies as a product wait on that.
  https://developers.google.com/my-business/content/prereqs
- **Sellable pieces for the register that are open source.**
  node-thermal-printer (MIT, Epson and Star over TCP or a Windows driver)
  for kitchen tickets from a Node agent on the restaurant PC; Evolution API
  (Apache-2.0, official WhatsApp Cloud API mode) for order texts, which the
  /do market already wants; httpSMS (AGPL) turns an Android phone into an
  SMS gateway for order-ready texts. Cal.diy (MIT since April 2026) for
  intake-call booking on the studio site.
- **Workflow engines.** Trigger.dev (Apache-2.0, TypeScript, cron, human
  approval waitpoints, Vercel-native) is the only one that fits a Node shop
  on Vercel without Docker; Activepieces (MIT core) if a client ever needs a
  UI they can touch; n8n's Sustainable Use License forbids reselling it
  hosted, so it is out for anything sold.

## Do not adopt

- Patchright Enhanced (unlicensed, no extraction code). Agent-Reach (Python,
  cookie-based, ban warning). browser-use and Stagehand (need a model key,
  which breaks the subscription rule). Camoufox and nodriver (Python,
  fingerprint drift). Firecrawl self-hosted (Docker, no adapters). Every
  BizBuySell or obituary scraper on GitHub (2019 to 2023 one-offs). Michigan
  SOS moved to the MiBusiness Registry Portal in June 2025 and no wrapper
  exists; keep it a manual step.
- Twenty CRM, Invoice Ninja, Crater: heavier than a one-person ledger and
  Stripe already invoices.
- Higgsfield as "open source." Evaluate it as a vendor with a skill file.
